### 2026-11-10 — Verify recommendation can call product_catalog over gRPC

ERRORS encountered while building the host-side smoke check:

- `ModuleNotFoundError: No module named 'grpc'` when running with the system `python`.
- `ModuleNotFoundError: No module named 'demo_pb2'` when switching to the recommendation virtual environment.
- `NameError: name 'meets_success_rule' is not defined` because the success-rule placeholder had not yet been replaced.

## TRIED

1. Checked the recommendation project virtual environment; it has `grpcio` installed. Used its Python interpreter rather than installing packages into the system Python.
2. Added `PYTHONPATH=application/recommendation` so Python could import the generated `demo_pb2.py` and `demo_pb2_grpc.py` modules from the application directory.
3. Replaced the undefined placeholder with `if len(response.product_ids) == 0:`. A non-empty list is the success condition for this check.

## FIX / verification

The owner ran this command from the repository root while the Compose services were running:

```bash
PYTHONPATH=application/recommendation application/recommendation/venv/Scripts/python.exe Scripts/recommendation/verify_recommendation.py
```

It returned five product IDs and exited successfully:

```text
['66VCHSJNUP', 'HQTGWGPNH4', '9SIQT8TOJO', 'OLJCESPC7Z', '1YMWWN1N4O']
```

This verifies that the host-side script reached recommendation through `localhost:9550`, and that a `ListRecommendations` request with no excluded product IDs returned catalog product IDs. The Compose port mapping is `9550:9001`; recommendation calls product-catalog at `product_catalog:3550` on the Compose network. This is a local-container verification, not an AWS deployment.

## What I learned

- The Python interpreter controls which installed packages are available; the project virtual environment has `grpcio`, the system interpreter did not.
- Python searches its script directory and installed module paths. `PYTHONPATH` adds the directory containing the generated protobuf modules.
- The smoke check tests a real request and response. A running container alone would not prove that recommendation can fetch products.

## Interview line

I verified the service-to-service path by sending a gRPC request to recommendation and checking it returned product IDs from product-catalog.
